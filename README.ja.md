# 『AI駆動開発の変更統治』実行教材

Zennの技術書『AI駆動開発の変更統治』第1版（1.0.0）に対応する、**再実行可能なローカル教材**です。書籍本文・有料章・書籍の図版は、このリポジトリには含まれていません。

- 教材の版：`1.0.0`。リポジトリ：https://github.com/kanaria007/ai-change-governance-materials
- 教材ID：`ai-change-governance-materials-1.0.0`
- 書籍の公開先：日英共通の[書籍リンク / Book links](BOOK_LINKS.md)で案内します。このファイルはリポジトリのデフォルトブランチで更新し、教材の照合対象には含めません。タグやダウンロードしたZIP内のコピーは、取得時点の案内です。
- 利用条件：このリポジトリの教材コード・付属文書は[MIT License](LICENSE)。**書籍本文と図版はMITの対象外**です。

## 何を確かめられるか

| 教材 | 主なファイル | 確かめること |
|---|---|---|
| 基本モデル | `lab/change_control.py` | 証拠の鮮度、反例、実行権限 |
| 操作範囲別モデル | `lab/coverage_control.py` | 必要な確認の漏れ、限定有効化、候補構成と稼働構成の分離 |
| 探索実験 | `lab/route_discovery.py` | 経路の探索方法を比較し、見落としと適用範囲を調べる |

**注意：本番用ソフトウェアではありません。** 実際のAIモデル、Gitのマージ、外部デプロイは行いません。教材のPythonコードには、信頼済みサンプルを`exec()`で実行する部分があります。出所を確認していないコードを入力しないでください。権限の隔離や実環境の安全性は保証しません。

## 準備と実行

実験結果はPython **3.13.5 / Linux** で取得しました。教材本体の実行に外部ライブラリ、APIキー、ネットワーク接続は必要ありません。

GitHubからコードを取得した場合は、リポジトリのルートで次のコマンドを実行します。

```bash
python --version
python verify_package.py
cd lab
python -m unittest -v
python run_experiments.py --output rerun-results.json
python run_expansion.py --output rerun-expansion.json
python runtime_scenarios.py
```

環境によっては`python`を`python3`に読み替えてください。

モデルの単体テストは**107件**です。基本31件、操作範囲別37件、探索16件、候補と稼働状態の分離23件で構成します。CI記録スクリプトのテスト8件と、配布物照合スクリプトのテスト13件は別集計です。テスト件数を品質保証率として解釈しないでください。

### 書籍第1版との照合

`EDITION.json`で教材IDを確認できます。書籍の付録に記載された`FILE-MANIFEST.json`のSHA-256を使えば、書籍と教材の版の対応も確認できます。

```bash
python verify_package.py --expected-manifest-sha256 sha256:＜書籍付録に記載された64桁の値＞
```

この行は説明用です。`sha256:＜...＞`を本書に記載した実際の値に置き換えてください。引数なしの場合は、収録一覧に載ったファイルとその内容だけを照合します。この照合は発行者の認証やコードの安全性を証明しません。

### 結果ファイル

| ファイル | 内容 |
|---|---|
| `lab/results.json` | A〜Fの基本ケースと、全件再検証との比較 |
| `lab/expansion-results.json` | E1・E2の判断、探索方法の選択・適用・限界 |
| `lab/runtime-boundary-results.json` | 候補の保留、稼働版の維持、稼働不一致時の停止 |

再実行時は収録済みの結果ファイルを上書きせず、`rerun-*.json`を使ってください。実行時刻や環境情報まで完全一致する必要はありません。

## CIとGitHub Actions

`.github/workflows/lab-checks.yml`は、`pull_request`、`merge_group`、`main`へのpush時に教材のファイル照合とテストを実行するための定義です。`examples/ci/collect_lab_result.py`は、対象のGitリビジョン・入力ファイル・実行結果を記録します。

同梱の実験結果はローカルで取得したものであり、GitHub Actionsで実行された結果として提示してはいない。実行記録ができても、PRのコードが自分で出力した`PASS`を本番変更の承認に使用してはいけません。詳細は[`examples/ci/README.md`](examples/ci/README.md)を参照してください。

## 本書の対象範囲

教材は候補構成を更新しても許可済みの稼働構成を変えず、稼働中の観測が不一致・取得不能な場合にはローカルの実行経路を止めます。ただし外部の認可基盤、永続的な操作記録、GitHub上の承認ゲート、外部環境での復旧は実装していません。

入力、評価器、合成ケースは同じ制作過程で用意しています。ローカルでの結果一致を、独立した未知問題への性能や実際の開発生産性の証拠として扱わないでください。
